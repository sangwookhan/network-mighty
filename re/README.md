## 핵심 사실

**카드**: `int` 하나. 0=없음, 1~52 = `(무늬-1)*13 + 숫자`(무늬 1♠ 2◆ 3♥ 4♣, A=1), 53=조커. 점수카드 A/K/Q/J/10 (덱 전체 20점).
마이티 기본 ♠A(기루다가 ♠면 ◆A), 조커콜 기본 ♣3(기루다가 ♣면 ♠3) — 규칙으로 변경 가능.

**덱/인원**: 3마 33장, 4마 43장, 5·6마 53장. 10장씩(6마는 8장) 배분, 나머지가 바닥패. 6마는 당선 후 한 명 탈락.

**한 판 흐름** (`FUN_004225b0`, 상태 int `CState+0x04`):
```
0 딜(셔플 4회) → 딜미스 검사
1 선거(공약: 기루다+목표점수, 포기, 딜미스 선언) — 전원 포기/딜미스면 재딜
   [6마] 당선자가 카드 지목 → 소유자 탈락 → 재셔플·2장씩 추가
2 당선자: 바닥패 수령 → 3장 버림 → 기루다/목표 변경(가능 시) → 프렌드 지정
   (카드 프렌드 / 플레이어 / 초구 프렌드 / 노프렌드)
3 10트릭 (GetAvList로 합법 카드, PowerComp/GetWinner로 승자)
4 정산 (FUN_00421240) → 다음 선 = 주공(또는 규칙에 따라 프렌드)
```

**네트워크**: 방장 PC가 서버 겸용, 기본 포트 4111, 최대 6석. 프레임 `[int32 len][int32 len][payload]`(LE), 문자열 CP949 NUL 종료.
대기실 메시지 1/2/3/4/5/6/1000(채팅)/-3(에러·추방), 게임 메시지 100·0x67(덱), 0x65(공약), 0x66(6마 탈락), 0x68(당선 확정+버린 3장), 0x69(카드).

**AI**: `MaiGetPlay`가 `CPlay` 객체(가상함수 8개: OnBegin, OnElection, OnKillOneFromSix, OnElected, OnElectionEnd, OnTurn, OnTurnEnd)를 돌려줌. 상태는 export된 `CState`/`CCardList`로 직접 읽음.
- BSW(내장): 모든 패를 보고 시뮬레이션 — 공정하지 않음
- Xiao: 무늬 보유 확률 추적 + 주공팀 확률 — 포팅 대상으로 적합
- Ghost: 합법 카드 중 무작위 — 인터페이스 참조용
- BSW·Xiao 모두 공약 평가에 **바닥패를 몰래 봄** → 포팅 시 제거 필요

## 웹 버전 설계에 주는 시사점

1. **원작 프로토콜은 그대로 쓰지 말 것.** 원작은 락스텝 복제 방식이라 서버가 **덱 전체를 모든 클라이언트에 전송**하고 각자 같은 루프를 돌린다 → 패가 모두 노출되고, 채팅 발신자 위조 가능, 끊기면 판 종료.
2. **서버 권위형으로 재설계**: 서버가 `CMFSM` 루프와 규칙 판정을 소유하고, 클라이언트에는 자기 패만 보낸다. 원작 메시지 단위(BID/KILL/ELECTED/PLAY/CHAT)는 "클라이언트 의도"로 그대로 쓰면 된다 (02 §6).
3. **FSM 이식이 쉽다**: 원작 FSM은 "플레이어 메서드 호출 → 이벤트 대기" 구조라 `await player.onElection(...)` 형태의 async 루프로 1:1 옮길 수 있다. 사람/AI/원격 플레이어가 같은 인터페이스 → 끊긴 자리를 AI로 교체하기도 쉽다.
4. **사용자 입력 지점은 5곳**: 공약(출마), 6마 탈락 지목, 바닥패 버리기·공약 수정, 프렌드 지정, 카드 내기 (+조커 무늬 선택/조커콜 여부).
5. **규칙 엔진은 순수 함수로**: `GetAvList`, `PowerComp`, `IsValidNewGoal`, `IsDealMiss`, 정산 — 01의 의사코드를 TypeScript로 옮기고 프리셋 12종으로 테스트.

## 원작 버그로 의심되는 부분 (웹 버전에서 결정 필요)

- 옵션 대화상자의 점수 방식 저장이 2번째 항목부터 한 칸 밀림 ("눈에는 눈" → "위험 보상"으로 저장)
- 딜미스 옵션 0x23/0x24, 노기·노프 2배 옵션 0x33/0x34는 코드에서 읽지 않음 → 노기·노프 2배는 항상 적용
- 딜미스 조커 옵션(0x27)이 조커 보유 여부를 확인하지 않음
- 최대 공약 25 허용 시에도 20 이상 부르면 선거 즉시 종료
- 프렌드 카드를 아무도 안 가진 경우 정산에서 인덱스 -1에 기록
- 당선 후 기루다 변경 시 요구 증가분이 버리기 전 +2 / 후 +1로 불일치(실제 적용은 +1)

## 남은 불확실성

- `CPlayer`/`CPlay` 가상함수 이름은 호출 순서로 추정 (기능은 확인)
- 정산 함수는 01(디스어셈블 검증)과 03의 설명이 세부에서 다를 수 있음 → 01 기준, 구현 시 원작 실행 결과와 대조 권장
- 0x65 마지막 필드, State +0x78·+0xd4~0xdc 필드 의미
- 일부 규칙 플래그의 정확한 의미는 `MIGHTY.HLP`(미분석)로 보완 가능
- Xiao/BSW 가중치·벌점 테이블 개별 의미
