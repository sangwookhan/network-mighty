# @mighty/engine

마이티 규칙 엔진. 서버(판정)와 클라이언트(낼 수 있는 카드 표시)가 함께 쓴다. 순수 함수로만 구성했고, 상태나 입출력이 없다.
근거 문서: `re/01_game_logic.md` (원작 Mighty Network 3.2 디컴파일 분석)

| 파일 | 내용 |
|---|---|
| `card.ts` | 카드 인코딩(원작과 같은 정수), 세기, 점수카드, 마이티/조커콜 결정, 카드·공약 이름 |
| `rules.ts` | 규칙 옵션 타입, 원작 14글자 규칙 문자열 인코드/디코드 |
| `presets.ts` | 원작 프리셋 12종 |
| `deck.ts` | 인원별 덱, 셔플(Fisher–Yates), 분배, 6마 탈락·재분배 |
| `trick.ts` | 낼 수 있는 카드(`legalPlays`), 트릭 승자(`trickWinner`), 조커콜 선언 가능 여부 |
| `election.ts` | 선거 진행(`startElection`/`applyBid`), 공약 유효성, 딜 미스, 당선 후 최종 공약 |
| `friend.ts` | 프렌드 지정 유효성과 프렌드 좌석 결정 |
| `describe.ts` | 프리셋 선택 화면용 설명 (핵심 요약 + 표준 규칙과 다른 점) |
| `scoring.ts` | 정산(점수법 5종, 런·빽런·노기·노프 배수, 주공:프렌드 분배, 파산 처리) |

```bash
npm test                # 테스트
npm run presets         # 프리셋 12종 설명 출력
npm run presets -- 6    # 6번(신촌 5마)만
```

## 원작과 달라진 동작 (원작 버그 수정)

| # | 원작 | 이 엔진 |
|---|---|---|
| 1 | 옵션 화면에서 점수법을 저장하면 두 번째 항목부터 한 칸씩 밀림 | `scoreMethod` 하나의 값으로 저장 |
| 2 | "점수카드 0장 / 모두 점수카드면 딜 미스" 옵션을 읽지 않고 항상 적용 | 옵션대로 적용 |
| 3 | "노기루다 / 노프렌드 2배" 옵션을 읽지 않고 항상 2배 | 옵션대로 적용 |
| 4 | "조커가 있으면 점수카드 하나 제함"이 조커 보유를 확인하지 않음 | 조커가 있을 때만 |
| 5 | 기루다를 바꿀 때 손패 13장이면 +2, 버린 뒤면 +1 (실제 흐름에서는 +1) | 옵션대로 항상 +2 |
| 6 | 최대 25까지 허용해도 20 이상 부르면 즉시 당선 | 최대 공약(20 또는 25)에서만 즉시 당선 |
| 7 | 프렌드 카드를 아무도 안 가졌거나 초구 프렌드가 주공이면 `money[-1]`에 기록 | 프렌드 없이 주공이 전부 받음 |
| 8 | 노기루다로 기본보다 1 낮게 불러 이기면 금액이 음수가 될 수 있음 (이기고도 잃음) | 0 미만이면 0 |

8번은 엔진을 만들면서 새로 찾은 문제다.

### 프리셋 12종의 옵션 보정

원작은 2, 3번 옵션을 읽지 않고 항상 적용했다. 그래서 원작 프리셋 문자열에는 이 옵션이 꺼져 있어도, 실제 게임에서는 노프렌드 2배와 "모두 점수카드면 딜 미스"가 항상 적용됐다.
`presetRules()`는 원작에서 체감하던 결과와 같도록 다음 옵션을 **켠 값으로** 돌려준다 (2026-10-18 결정).

- `noKirudaDouble`, `noFriendDouble` (노기·노프 2배)
- `dealMiss.noPoints`, `dealMiss.allPoints` (점수카드 0장 / 모두 점수카드면 딜 미스)

또한 **표준 5마**는 첫 공약자(딜러)가 처음에 포기할 수 없도록 `dealerCanPassFirst` 를 끈 값으로 돌려준다 (원작 값은 허용, 2026-10-18 결정).
포기할 수 없는 첫 공약에서 화면은 '기노'(노기루다 + 기본 공약 13)를 기본으로 골라 둔다.

원본 문자열 그대로의 값이 필요하면 `decodeRules(preset.code)`를 쓴다. 방장이 옵션을 직접 끄면 엔진은 옵션대로 동작한다.
